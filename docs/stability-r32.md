# R32 截图与运行登记稳定性修订

R31真实使用反馈包含两类问题。28987的窗口画面可见，但截图多次报告空白，后来成功，402242也有同类失败。398863的一次窗口预览在运行副本复制后的登记更新处失败，播放器未创建，随后预览成功。用户另记得桌面应用时“试播失败”，目前不能把它和这次窗口日志合并为同一事件。

## 本批修正

截图仍只针对当前自有预览的渲染客户区。保留进程、创建时间、窗口父子关系、run token、资源SHA-256和尺寸检查，未扩大到桌面或其他窗口。每次请求最多六次取帧，等待策略总预算1500ms；接口阻塞仍受原独立捕获任务5秒预算及1500ms取消收尾保护。持续空白、低信息量、目标失效或取消均不发布图片，判黑阈值保持原样。每次尝试仅记录接口结果、尺寸和图像统计；失败图像不保存。

修正捕获错误沿用wait-for-controller-go旧阶段名的问题，按目标核验、接口捕获、等待、有效性与发布分阶段记录。新请求清空旧错误文字；保存中禁用重复截图，关闭或切换仍走已有取消和等待链。封面绑定使用受保护的原子更新，替换失败保留旧封面；播放确认独立。

JSON更新改用每次独立临时文件、同一目标读取与写入的跨进程互斥及500ms统一预算。对共享/锁定及Windows 1175、1176等明确替换错误有界重试，取消检查覆盖锁等待与重试。永久失败保留原异常、HRESULT、目标和尝试次数。运行登记的临时文件放在拥有根，避免半写文件进入单条运行材料的归属验证范围。程序不先删除旧登记。同一数据根内由本机制登记的旧版本运行材料继续按完整请求身份核对，避免新版本因旧失败材料的日志版本名不同而拒绝下一次准备；不会扫描或接管其他历史目录。

## 证据边界

隔离红例证实原来会立即拒绝短暂文件占用和第一张黑图。并发压力测试还捕捉到替换竞争，随后以串行化修正。原实际异常的具体占用方与捕获接口返回空白的渲染时序仍未证实。合成有效帧、处理器通过和原子更新压力测试不能证明真实引擎捕获已稳定，仍需一次最小差异体验。

个人库、组件配置、来源、封面、确认、设置和StoreId沿用。升级须等待相关个人实例正常结束，使用目标版本的正式绑定与版本切换机制，保留旧版本及其证据。旧R28—R31分项有效结果继续分别继承，其他Windows和第三方条件保持原有边界。
