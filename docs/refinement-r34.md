# R34 宿主提交、首页与编辑交互修订

## 首次预览失败

R33本机317495的一次预览在HostResources.Stage将短暂存目录提交为host时得到错误5，播放器尚未创建。同一资源下一次预览成功，不能覆盖首次失败。原故障运行输入14,089,328字节按失败预算保留；只读复核时该run已无宿主暂存/host目录，旧日志没有精确记录暂存回收时点，不能仅凭后来的目录缺失证明当时所有材料已清理。

自有复制读取流在提交前均已释放，实际Stage夹具可独占打开全部复制文件。一个无Delete共享的目录读取句柄实验没有重现访问拒绝。这些证据不能确定原占用方、ACL或安全软件行为。

在实际Stage目录提交调用点，用TEST_BUILD的自有24行替身契约建立native5故障模型。模型能检出原来单次提交立即失败的行为，不能证明历史现场的具体拒绝原因已经重现。

## 有条件恢复与诊断

提交前后核对目录卷/文件索引/创建身份、重解析点、精确目录树、四份完整文件哈希以及目标为空。仅此目录提交点的错误5、32、33在归属保持且目标不存在时最多尝试4次，额外恢复调度预算800ms。每个文件IO和完整核验仍服从原worker20秒准备取消预算，系统调用本身无法承诺毫秒级强制中断。

目标竞争、源身份/内容变化和不安全路径均不继续提交。目标存在时不覆盖，归属变化时保留暂存。提交可能已完成而系统返回错误时，仅接受原目录身份和完整文件集匹配的最终目录。取消走原有任务取消链。

每run新增host-stage-result.json，记录原始第一次提交异常、HRESULT、源和目标、每次尝试、提交/暂存清理或保留结果。worker结果分别记录宿主暂存与已提交运行材料，输入副本仍按原独立空间策略处理。

失败首页改为“播放失败，任务已结束”，同时说明宿主材料与运行副本回收/保留/待确认。进程结束和文件回收分开表达，不把故障保留称为全部清理完成。

## 首页与设置

移除首页右侧资源摘要及占位。主要预览/设为桌面、停止/隐藏改成并排两组；重命名/更多并排。封面截图、选择图片、移除和详情归到“更多”。卡片右键重命名保持。

右侧采用实际高度预算，压缩重复封面和留白。小高度时省去右侧重复封面，左侧卡片封面仍在。默认可用工作区至少1280×720，100%、125%、150%按构造控件几何与布局计算检查主要按钮完整可见。壁纸列表与设置长内容继续可滚动，极小或更高缩放的实际观感未验证。

设置分组按用户授权更换为固定Material胶囊/下划线状态，直接依实际SelectedIndex绘制，不再用动画中间位置。保持四组内容和原功能。

卡片状态仅去掉“桌面未验证”展示，原确认字段及播放保护不改。独立编号统一显示“ID”，缺少官方编号时显示完整“本地条目”标识。壁纸标题与自定义名称不改，历史JSON字段、token和原日志保持。

## 重命名与图标

非模态编辑器的取消按钮增加显式关闭处理，Esc、右上角关闭和保存失败后的取消均结束编辑且不写名称。两个实际入口仍共享工厂与处理器，关闭后按当前选中恢复合理焦点。用户真实焦点体验仍待确认。

MaterialDialog为每个自有顶层窗体加载独立蓝色折框图标克隆，处置时释放本窗体图标。设置、重命名及其他继承该基类的自有窗口统一采用，系统文件选择器保持原生行为。

## 验证范围

实际Stage夹具、原始失败材料、目录提交故障模型、非模态按钮事件链、离屏页签绘制、无Show控件几何、新进程名称读回与真实引擎/视觉反馈分别记录。没有自动启动真实引擎、播放或控制窗口。真实重试只需317495窗口预览及本轮UI差异，不重做桌面、截图、导入和旧整套验收。
